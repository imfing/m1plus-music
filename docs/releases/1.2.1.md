# M1+ Music Navidrome 1.2.1

Unofficial Shanling M1 Plus firmware based on the upstream M1+ Music 1.2.1 release, with Navidrome/Subsonic integration and library/UI fixes. The upstream project and its features, including Tidal, are retained. See the [upstream project](https://github.com/imfing/m1plus-music) and the repository [acknowledgements](https://github.com/iamgauravmishra/m1plus-music-navidrome#acknowledgements).

## Navidrome and Subsonic

- Save server URL, username and password on the SD card; reconnect automatically using the saved settings. HTTP and HTTPS URLs are supported. HTTP is unencrypted and should only be used on a trusted network.
- Sync a paged metadata index, explicitly refresh it with confirmation, search the server catalog, and browse Songs plus a separate DSD Downloads section. Server connection status is visible. Lists support grid/list modes, artwork, alphabet navigation and download progress.
- Stream supported tracks over Wi-Fi using the server's raw audio endpoint, without requesting transcoding or processing audio in the player. Supported tracks can instead be downloaded to SD, with progress and resumable partial transfers where the server supports HTTP ranges.
- Use the same cached artwork for the Navidrome track list and Now Playing; no second artwork cache is created.
- Browse regular server tracks from the stock Songs, Albums, Artists, Album Artists, Genres and Composers libraries, global search, Cover Flow and the virtual iPod. The virtual layer leaves the stock music database and scanner intact.
- Show a green dot only on tracks that will stream from the server. A local match or downloaded file is treated as local and takes precedence in Libraries. The Navidrome page still lists the complete server catalog.
- Keep mixed playback queues in the order of the current library view. Un-downloaded DSF/DFF tracks are excluded from stream/library queues because the stock player does not handle them correctly; DSD files are available for explicit download and appear as local tracks after download and SD indexing.
- Background artwork work yields to playback and downloads. A successful DSD download triggers a background SD library refresh.

## Other fixes in this update

- Correct library playback and metadata for server tracks, including album-artist separation, category matching, global search, recent-played queues and album duration totals.
- Keep album art available in album listings and Cover Flow; include virtual server albums and tracks in the iPod-style Pod browser.
- Repair return/back handling in Cover Flow, album and artist library views, and Pod Cover Flow to avoid the previously observed hang/reboot paths.
- Align Navidrome song and DSD download row actions with the right edge and provide alphabet scrolling in DSD Downloads.
- Keep the Songs list's Play/Shuffle controls clear of the alphabet rail and optimize A–Z section setup for the common sorted-list case.

## Limits and safety

- DSD/DSF/DFF streaming is not supported. Download those files first; the Navidrome integration does not expose them in stream-only library queues.
- Offline use requires downloaded files. Synced server metadata is a snapshot and requires a manual or credential-triggered sync to refresh.
- HTTP sends credentials and audio without transport encryption; prefer HTTPS outside a trusted local network. HTTPS certificate validation uses the firmware CA bundle.
- The stream queue is limited to 64 tracks; mixed library queues are limited to 4,096 entries; the synced catalog is limited to 100,000 tracks. Artwork caching is bounded and may leave covers unavailable when images fail validation or exceed its limits.
- Raw streaming avoids client-side transcoding and the device has displayed the server track's source sample rate and bit depth in user testing. Those observations do not establish sample-for-sample identity at the DAC for every server, format, or playback path.
- This update changes the app payload and UI assets through the existing update path. It does not patch bootloader or recovery code. Firmware installation still carries device risk: verify the checksum, keep the player charged, do not interrupt installation, and keep stock recovery files available.
