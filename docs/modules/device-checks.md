# Device checks

Record the build tag, device/card, result (pass/fail/untested) and capture for each applicable
check. This is a checklist, not a record of completed testing. Historical observations stay
in [history](../history.md); feature modules retain their detailed edge cases.

If `ps` shows plain `wpa_supplicant` (no path), ours failed its `-v` check or its start: send `ls -l /usr/lib/m1plus` and `/usr/lib/m1plus/wpa_supplicant -v` output. |

| WIFI-08 | Wi-Fi page, join ([details](wifi.md)): join an open network, a WPA2 network (the password page, WIFI-14; a wrong password on a saved network toasts "Couldn't connect" and the network stays saved), a hotspot named with a typographic apostrophe (`Sam’s iPhone`: shown with the apostrophe, joins; stock's page may fail on it) and a hidden network (Other..., WIFI-15). | WIFI-10 | Wi-Fi page, files ([details](wifi.md)): after joining a WPA3 network `/mnt/data/m1plus/wifi-networks` holds its block (`sae_password`, `key_mgmt=SAE`, `ieee80211w=2`) and `/mnt/data/wpa_supplicant.conf` holds none of it (only `key_mgmt=NONE` / `WPA-PSK` blocks); reboot: it reconnects. | WIFI-11 | Wi-Fi page, supplicant failure ([details](wifi.md)): with `/mnt/mmc/m1plus-off` present save a WEP network through the stock page (All System Settings > Wi-Fi), remove the file and connect: `ps` shows plain `wpa_supplicant` and Wi-Fi works through stock; the page lists WEP APs and toasts only. | WIFI-12 | Wi-Fi page, hub row ([details](wifi.md)): All System Settings > Wi-Fi opens our page (same look and rows as Settings > Wi-Fi, not the stock list); join and add a network there, Back returns to the All System Settings hub with no stock Wi-Fi page left behind, and the network is still saved after a Wi-Fi off/on (`/mnt/data/wpa_supplicant.conf`). Bluetooth in the same hub still opens stock's page. With `/mnt/mmc/m1plus-off` present the same row opens the stock Wi-Fi page and stock's supplicant serves it (the WEP route: save a WEP network there, remove the file and check WIFI-11). |
| WIFI-13 | Wi-Fi info page ([details](wifi.md)): the info glyph of every row (saved, connected, not saved, out of range) opens a page titled with the network's name (a long or apostrophe name cut with an ellipsis / shown as UTF-8) against `out/preview/settings-info.png`. Saved: Forget This Network (Delete Record?, No keeps it, Yes forgets it for good, also after a reboot, and goes back to the list), a card with Security (Open, Enhanced Open, WPA/WPA2, WPA2/WPA3, WPA3, Enterprise match the AP) and, only while it is the connected network, IP Address and Router (the router is the gateway: compare with the phone / `route -n`), and an Auto-Join switch. Auto-Join off: the switch turns off, `/mnt/data/wpa_supplicant.conf` (or `wifi-networks` for WPA3) gets `disabled=1` for that network only, a reboot does not reconnect to it by itself, the stock page still lists it; **turning it off on the connected network disconnects it (the supplicant does that): note whether it does**; on again: the line is gone and it joins by itself. Join a network from the list, then forget another from its page: no other saved network got `disabled=1` (`cat` both files). **Brief enable after a select** (`wp_reenable` sends `ENABLE_NETWORK all`, then `DISABLE_NETWORK` for the Auto-Join-off ids): with an Auto-Join-off network in range and stronger, join a different saved network from the list ten times: it never associates with the off one, not even briefly (no connected row or check for it, `wpa_cli status` never shows its SSID), and its `disabled=1` line is still there afterwards. Not saved: Security and Join (open joins; secured asks for the password; WPA3 with the supplicant off, Enterprise and WEP toast), then the page goes back. With the page open: the connect's address and router appear, a network that leaves the scan stays on the page and Forget still works, Wi-Fi turned off from the pull-down returns to the list. |
| WIFI-14 | Wi-Fi password page ([details](wifi.md)): tap a secured network that is not saved (and, from its info page, Join): the page "Enter Password" against `out/preview/keyboard-pass.png` (the Wi-Fi password panels): the grey line names the network (a long or apostrophe name), the card with Password, the dots and the eye, the pad on lowercase, **Join** dimmed. Chinese (Pinyin) on: the language key and pinyin on the Name, never on the Password, and back on the Name again without a second wait for the engine. If stock's supplicant is running after a fallback (ours failed `-v` or its start): WPA2/WPA3 joins as WPA2, WPA3 toasts "This network isn't supported" and the picker keeps the old choice. A name that is not there (a typo) or a wrong password: after about 20 s (or when the supplicant marks it) "Couldn't connect" for an open network and, for a secured one, the Join Wi-Fi Network page again with Name and Security kept, an empty Password and "Incorrect password" under card 2 (gone at the first character), **no network of that name stays** in either file. ## Library and playback

- **ALB-01 — Albums:** switch grid/list in place, retain the first visible album and mode after
  reboot, and return from an album to the same position. Check long labels, missing covers,
  pressed rows, sharp tiles and a large library. [Details](albums.md)
- **CF-01 — Cover Flow:** portrait/landscape, artist scope, ends, drag/fling/snap, side/centre
  taps, first cache build, cancel and rebuild. The navbar stays usable. [Details](coverflow.md)
- **SONG-01 — Songs:** title collapse, pinned letters, all rail sections/bubble, search, each
  sort, select-all, add/delete and return position. Check a large library; covers load after
  scrolling stops. [Details](songs.md)
- **NAV-01 — Album/navbar:** one seamless capsule, contained pressed highlights and no leftover
  pixels in button gaps. Play resets in-order mode; Shuffle and track taps use the expected
  queue. Look up album returns correctly to Now Playing. [Album](album-page.md), [navbars](navbar.md)
- **PLAY-01 — Now Playing/lock screen:** sharp rounded covers, tint changes, neutral missing
  art, remaining time, transport/favorite/More controls, translucent card and swipe behaviour.
  Check idle/no-queue and charging states. [Now Playing](nowplaying.md), [lock screen](lockscreen.md)

## Home content

- **HOME-01 — Mini player:** absent with no queue and on the normal menu; appears within a
  tick for playback. Check long titles, transport/track updates, Now Playing return, dialogs,
  pull-down and the final row scrolling clear above it. [Details](minibar.md)
- **HOME-02 — Blur:** smooth scrolling and track changes, rounded glass without seams/colour
  casts or persistent sharp patches. Compare `m1plus-noblur`; BGRA5551 intentionally omits blur.
- **HOME-03 — Recently Played:** newest-first covers, one entry for compilations, one to three
  rows without layout jumps, lazy cover loads and no stutter. Check missing/deleted albums,
  taps versus drags, coasting catch, setting persistence and reboot. [Details](recent.md)
- **HOME-04 — Daily Mix:** responsive creation/regeneration, readable card over varied palettes,
  expected songs/artist limits, play/shuffle/track taps and correct detail page. Check settings,
  reboot, card swap/no card, missing covers and Add-to-playlist behaviour. [Details](dailymix.md)
- **HOME-05 — Cache pill and sync icon:** with covers missing (Developer > Clear Cover Cache, then Home) the pill "Checking library…" (empty bar, no count; "Rebuilding covers…" after Rebuild Covers) appears at once, and about 5 s after Home is in front it becomes "Preparing covers n/m"
  with the bar growing and the list below it intact; "Measuring tracks n/m" follows. The x stops the pass at once without a stall, the pill hides, and the pass does not return
  on leaving and re-entering Home until a reboot or Settings > Library > Rebuild Covers (which then runs). While any build runs, on Home, Albums, Songs, Cover Flow and Settings, the static sync glyph
  shows between Bluetooth and Wi-Fi in the status bar and in the pull-down's bar, clear of the clock (also with Battery Percentage on); it goes out when the build ends or is stopped. Playback and scrolling stay smooth during
  a build (the worker runs at nice 10). With the cache complete, leaving and re-entering Home shows no pill and does no scan; after playing a song no pill shows (same library); adding an album shows it about 5 s later and builds; the x while it waits cancels it, and after a reboot it returns. Leaving Home mid-build (or during the wait) and coming back restarts it after about 1 s, not 5. Check the pill's text and bar in several languages. [Details](homecover.md), [sync icon](lineout.md)
