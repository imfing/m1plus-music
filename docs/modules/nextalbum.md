# Continue Playing > Next Albums (continue with the next album)

Settings > Playback > **Continue Playing** is a value row (Off, the default, or Albums) that opens a picker with **Off** and **Next Albums**, a check on the chosen one and the grey hint "Plays the next album in the order of Albums, the artist or Cover Flow" (two lines). Next Albums: when a List play queue started from an album ends, the next album plays, in the order of the page that album was opened from. A third option, Auto Mix, is planned: the file value `2` and `NA_*` modes are left open for it, with no row yet. The row shows "Albums", not "Next Albums", at the right: label plus value must fit the 216 px between the label (x 58) and the value's right edge (x 280); "Continue Playing" (143 px at 21 px) plus "Next Albums" (99) does not in English, and the labels were chosen so that the shortest value text fits in all 13 languages (widest label + value: fr "Enchaîner" + "Désactivé" 164, es "Continuar" + "Desactivado" 181, ru "Продолжить" + "Альбомы" 188 of 216).

Two parts: the order an album was opened from, kept in memory (`na_note` .. `na_next_key`), and the end of the queue (hook 26, `na_end`).

## Setting

`/mnt/data/m1plus/playback-next-album`: `1` Next Albums; missing or anything else Off (`2` is reserved for Auto Mix). `na_setting` reads the file (`NA_ALBUMS` 1 or `NA_OFF` 0), `na_set(mode)` saves it (`home_write_atomic`; a mode that is not offered, or a failed save, changes nothing and returns -1) and drops the active source when it turns Off. `ACT_NEXTALBUM` 90, a value row on the Settings root after EQ (`VALUE_ACTIONS`, `VK_NA`, opens page 66, `NEXTALBUM_PAGE`, `m1plus_nextalbum`, the last of `PAGES`), glyph `skip-forward`, 13 languages; `ACT_NASET` 91, the picker rows (arg = the mode, a check on `na_setting()`). The file is the 34th entry of `SETTING_FILES` / `sf_files` (after `playback-eq`), so Settings Files and Reset All Settings list and delete it; `INFO_SFOLD` is now `INFO_SF + 44` and `INFO_DUR` follows it. Off, or while `/mnt/mmc/m1plus-off` exists, nothing is recorded or allocated (`enabled()` caches the file; `na_set` updates the cache).

## The order (`patch/nextalbum.c`, `nextalbum.h`, prefix `na_`)

A source is one reference counted block: `n` album keys (`cc_album_key` of the albums, in the order shown, at most `CC_CMAP_MAX` 4096), the `scope` (`CLASS_ARTISTS` / `CLASS_COMPOSERS`, 0 for the library), a deep copy of the artist row (`cc_copy_list`; NULL for the library), `own` (the album the page was opened on) and `cur` (the album now playing). Three slots hold it, so nothing frees what plays: `pending` (the note), `page` (the open album page's order) and `active` (the source of the queue that plays). A failed allocation or artist copy leaves no source (never a stale one).

| Step | Caller | Effect |
|---|---|---|
| note | `al_on_up` (patch/albums.c, library and scoped Albums page, grid and list) and `open_album` (patch/coverflow.c, library and artist Cover Flow) call `na_note_albums(albums, order, count, scope, artist_row)` just before `cc_open_album` | keys of `cc_row(albums, order, i)` over the shown order; the All Songs card (`ID_ALL_SONGS`) and Unknown Album (`REC_ID` -1) are left out; replaces the previous pending note |
| drop | the same callers, right after `cc_open_album` returns | `na_note_drop`: a note that `album_open` did not take is freed, so no other caller's album can inherit it |
| take | `album_open` (patch/albumpage.c), after its window is up: `na_page_open(key)` | the note becomes the page's order when the opened album's key is in it; otherwise (or with no note) the page has none. `ab_on_destroy` calls `na_page_close` |
| arm | `ab_play_at` (Play, the Shuffle pill, a track row; the single choke point to `so_play`) brackets `so_play` with `na_arm()` / `na_disarm()` | `na_arm` makes the page's order the active source (cur = own) and keeps the previous one aside; `na_disarm` puts the previous one back if no load happened (missing file, "Update Local Music first") |
| load | `sh_load_playlist` (hook 14, `mclLoadPlayList`) calls `na_on_load()` first | armed: the source is kept, the armed flag and the saved previous source are cleared; not armed (Songs, playlist, folder, Daily Mix, podcast, radio, DLNA, boot resume, Pod, playmore): the active source is dropped |

`na_next_key(cur, &out)` returns 1 and the key after `cur` in the active order; 0 at the end (no wrap), for a key that is not in the order, or with no source. `na_set_cur` / `na_cur` / `na_active` are the accessors for the album now playing (`na_end` moves `cur` on after an append; they are `noinline` so the tests can call them by name).

Sources of an order: the Albums page (library) and an artist's or composer's albums page (scoped), Cover Flow (library and scoped; same `cc_album_order`). Not sources, so they stop at the end of the queue as stock does: Recently Added, Search, Look up album, `covlist`, the Songs page's album rows, playmore, Pod mode, playlists, folders, Daily Mix, podcasts, DLNA, radio.

## Constraints

- Why the armed flag works: `ab_play_at` -> `so_play_with` -> `pod_open_player` -> `navigator_to_with_context("playing_page")` -> `playing_page_init` -> `start_player` -> `mclLoadPlayList` run on the UI thread inside that one call (`so_play_with` destroys its queue right after `open()` returns, because `start_player` has copied it). The test mock for the playing page therefore runs the payload's own `na_on_load` at the navigator call and reads the state there. Not verified on the device: whether Now Playing's init makes one load only (a second load in the same open would drop the source).
- No lock: the flags are single bytes and pointer words touched on the UI thread; a DLNA or refresh load on another thread can drop the source (it is a different queue then, which is right) and in the worst case races with `na_arm` for one tap.
- Only repeat off (stock mode 0) and the payload's Shuffle flag off may continue (`pod_shuffle_on()`, `mclGetPlayMode()` in `na_end`).

## The hook (hook 26, `na_end`)

`mclNextSong` (`0x5d5800`) is stock's Next: `mclAutoChange` calls it with `a0` = 1 from the main loop's idle tick (`on_wm_idle_status`) when a song ends, `next_music` / `change_music` with `a0` = 0 for the Next key and buttons. In List play (raw mode word `0xa0abe0` = 0) it tests `pos < size - 1` at `0x5d5950..0x5d5974` (a live read of the queue `*0xa0394c` and the position `0xa0abdc`) and plays pos + 1 through `mclStartPlayer` (`0x5d5920`); at the end it falls to `0x5d5988`, then the folder-callback check, `mclStop` (`0x5d59d8`) and `{mcl-orderstop}` for `a0` = 1, or the same song restarted for `a0` = 0.

The two words at `0x5d5988` / `0x5d598c` (`lw v0, GOT; lw v1, class word`) become `j pod_na_site; nop` (`tools/pod.py` `NEXTALBUM_SITE`, the shape of the Equalizer row stub). The stub calls `na_end()`, sets `$gp` again and jumps to `0x5d5950` on 1 (the test is read again: the queue is longer, so pos + 1 plays through `mclStartPlayer` for both `a0` values, no stop, no orderstop), else re-executes the two words and resumes at `0x5d5990`: stock's end exactly. `$s1` (= `a0`), `$s2` (the queue global), the frame and `$ra` (saved by stock at `0x24($sp)`) survive. `NEXTALBUM_PINS` (the prologue and frame, `move s1, a0`, the mode branch, `0x5d5920..0x5d5928`, the end test, the end branch, the stop / restart words, the dispatcher words in `loadLocalClassList` / `loadAlbumList` that choose the getters below, and each getter's prologue) fail the build on a different binary; the displaced words are checked again before the edit. Payload hook 24 ([payload](payload.md)); not reachable at boot (`tools/reach.py`); approved by the user 2026-11-09 although it is on the idle path (bounded work, stock's end on any refusal; [safety](safety.md)).

`na_end` continues only when all hold, in this order (each failure returns 0 and changes nothing, no toast): setting on and no kill switch (`enabled()`), a source (`na_active()`), DLNA's `dmr_serverflag` is not 1 (checked before any work: DLNA's threads also reach `mclNextSong`), Shuffle flag off, `mclGetPlayMode()` = 0, the playing position is the last of a non-empty queue, `na_next_key(na_cur())` has a next key (no wrap). Then:

1. The albums of the source's list into `*PDEQ_TOOLS_TMP`, no show list: the library through `toolsQueryDbTable(STOCK_DB_PATH, STOCK_ALBUM_SQL, STOCK_ALBUM_ROW, 0)` (the Albums list's statement; the Library filter hook applies); an artist's or composer's page through the stock getters `loadAlbumList` runs: `getAlbumByAlbumArtist` (`ARTIST_TYPE` 1, name = artist row field `0x24`) or `getAlbumByArtist` (field `0x18`) or `getAlbumByComposer` (field `0x20`); the Unknown Artist row (`REC_ID` -1) passes no name. The row whose `cc_album_key` is the next key (the All Songs card and Unknown Album skipped) gives the album name, copied to a 256 byte buffer (stock's browsing record keeps 0x100 bytes) before the scratch deque is cleared.
2. The album's tracks into `*PDEQ_TOOLS_TMP` with the **album page's own getter**, the one `loadLocalClassList(0xff10 / 0xff11 / 0xff14)` calls before it assigns the result to `*pdeq_showlist`: `getMusicByAlbum(album)`, `getMusicByAlbumAndAlbumSonger` / `getMusicByAlbumAndSonger(album, artist, 0)` or `getMusicByAlbumAndComposer(album, composer, 0)`. They run `toolsQueryDbTable` (so the Library filter applies) and stock's sort (disc, then track, comparator `0x4e9020`), so the order is the album page's by construction, and their SQL is stock's, not a copy. Neither they nor `na_end` touch `*pdeq_showlist` or the browsing record (`CLASSINFO`): no `cc_albums`, `loadLocalClassList`, `loadAlbumList` or `loadAlbumdetailList` call. (Deviation from the first plan, which was to lift the SQL into `QUERY_PINS`: the getters are the same code the page runs, so there is no copy to keep in step; their prologues and the choosing words are pinned instead.)
3. `upnext_add(rows, 1)` (at the end of the queue). Only `UPNEXT_ADDED` counts; any other answer (full, missing file, no memory, a stream play type, Radio running, DLNA) is "not appended". `REC_CLASS` of the new rows is stamped from the playing row by `pod_queue_insert` (the album page's class `0xff10` / `0xff11` / `0xff14`). On success `na_set_cur(next key)`, so the chain goes A, B, C. The scratch deque is cleared on every path.

`na_end` holds no lock; the payload mutex is taken once, inside the insert, after both queries, and released before the player starts. Work per album end: one album list query (the library's costs what the Albums list costs, as `cc_cmap_build`) and one track query, once per album on the idle path.

## Limits

- There is a gap between albums (the last song ends, then the next starts; not gapless). Gapless on or off makes no difference at the last song of a List play queue (no preload is open there).
- Sources are Albums (library), an artist's or composer's albums, and Cover Flow. Recently Added, Search, Look up album, the Songs page, playlists, folders, Daily Mix, Podcasts, Radio, DLNA and Pod mode are not sources and stop at the end as stock does.
- The source is memory only: lost on reboot (the resume plays the saved queue as stock does; `save_memoryplay_info` stores the playing row, play type and position, not the appended albums or the order) and dropped by any other queue load (`na_on_load`).
- Up Next and the Queue page show the appended album from the moment its first song plays (the append happens at the end of the last song); Previous goes back into the old album.
- Not verified on the device: whether Now Playing's init makes one `mclLoadPlayList` only (a second load in one open would drop the source before the first song ends); what the resume after a reboot does with an appended queue; the cost of the album list query on a large library (device check NEXT-01).
