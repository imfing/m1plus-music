# Timed cover page (bigcover_page)

**Sources:** `patch/bigcover.c`, `patch/covercache.c` (`cc_fit`, `cc_decode_fit`, the worker); `tools/pod.py` `BIGCOVER_*`; tests `test/pod/bigcover.py`, `test/coverflow.py` (`cc_fit`).

Stock opens `bigcover_page` from Now Playing's 500 ms page timer (callback `0x53cf48`, registered by `player_timer_start` `0x53c210`) after the counter at `0x97ccd0` runs out (20 ticks, about ten seconds, with Cover Mode on): `navigator_to("bigcover_page")` at `0x53d0ec`. The page's `img_playcover` is 320 x 320, `draw_type = scale_auto` (nearest neighbour), and stock's loader (`0x5296f8`) fills it from the shared 264 px `/tmp/coverpic.jpg` (cover source 2) or `/tmp/externpic.jpg` (3, 5; 5 is the `.downpic` file), so the artwork is enlarged 21 % and reads blocky. `COVER_SIZE` (264, `tools/mod_lockscreen.py`) is not touched: Now Playing, the lock card and the remote-control replies (92,161 byte limit) depend on it.

## Design

The page gets a 320 px picture of its own, made from the original track's art and shown 1:1; stock's 264 px picture stays underneath.

- **Hook:** `bigcover_page_init` `0x529a24` (payload hook 23), a PIC prologue hook like Now Playing's: `m1plus_bigcover_init` runs the stock init, then (unless it failed, the window is null, `/mnt/mmc/m1plus-off` exists, or the page has no `img_playcover`) starts the page's state. Chosen over the call site `0x53d0ec` because the page-init dispatcher (`0x4d10c8..0x4d10e0`, the only other reference to the string `"bigcover_page"`) calls the init for every way the page is built, so no entry path is missed and nothing of the stock timer or counter is touched. Entry paths found: only the timed open (`0x53d0ec`) calls `navigator_to` with that name (`stock.py strings bigcover`: two references, the dispatcher's strcmp and the timed open). `tools/reach.py`: neither site is reachable from `main/platform_init` with the navigator cut; the init runs only when the page is built, never at boot.
- **State** (`bc`, one page): the window, `img_playcover`, a 250 ms page timer (`bc_tick`), `EVT_DESTROY` on the window, `EVT_AFTER_PAINT` on the cover widget, and one 320 x 320 RGBA bitmap made on first use. No global paint or main-loop work.
- **Track identity:** the playing track's path (`cc_playing`), hashed; 0 for nothing playing or a path not starting with `/` (a stream). A change drops the job and the picture (`bc_drop`: `cc_build_stop`, the files, a repaint) and starts over for the new track in the same tick.
- **Job:** only when the cover source is the embedded art (2) or the folder's (3) and demo is not rewriting it (`np_cover_file`: a local track with art). **The source must belong to the playing track.** Stock's parser (`parseplaycover_thd` `0x4ded84`, a thread polling the start flag every 100 ms; `get_id3info` sets the flag and the path via `setparsecover_info` `0x4debb4`) is asynchronous: after a track change `COVER_SRC` keeps the last track's value until it has parsed the new one. The thread skips a path equal to `savecover_path` (`0xa04c3c`, `COVER_PARSED`, char[0x400]; `strcmp` `0x4df028`), sets `COVER_SRC` = 1 (`0x4df094`) while it works, stores 2 / 3 / 5 (`0x4df1fc`, `0x4df238`, `0x4df16c`) and only then, after the unlock, memsets and copies the track's path into `savecover_path` (`0x4df178..0x4df1a4`). So `COVER_SRC` in {2, 3} with `savecover_path` equal to the playing path (read without the mutex; a half-written or empty buffer is just unequal) means the source word is this track's; busy (1) or the previous track's path fail the check. The page requests only then (`bc_src`), keeps the requested source with the job (`bc.src`), and `bc_finish` drops the result unless the source and the path buffer still match (`bc_same`): the file is removed, the state returns to idle and the next tick asks again with the new source, inside the track's `BC_TRY_MS` budget counted from its first sight (a result is never shown for a source it was not made for, a source turning 5 or busy again is dropped and not retried while it stays so). The paint checks the same (`bc_same` with the track key) and a shown picture whose source moves on is taken off by the tick and asked for again. If the path stock stored were ever formatted differently from the queue's path the check never matches and stock's picture stays (the safe side). Residual risk: when the user goes A, B, A quickly, the instant between the parser storing B's source and copying B's path still shows A's path; the window is a few instructions and the parser parses A again right after, so a wrong source would last one request that `bc_same` drops at the next tick or paint.

Source 5 (the cached `.downpic/<track>.jpg`) is another picture the worker does not search, so the page leaves stock's picture for it (the simpler of the two options: no job, nothing drawn; the track gives up after `BC_TRY_MS`); the screen is lit and the shared worker is free (`cc_build_busy`, then `cc_build_open`): `cc_build_add_aspect(track, "/tmp/m1plus-bigcover.jpg", 320, source)` (`source` is stock's cover source word, 2 or 3), the Pod cover pane's transient job ([ipod](ipod.md) "Cover pane", [coverflow](coverflow.md)) with one difference: the job keeps the aspect ratio of an original whose longer side is exactly 320 (`pv_cover_aspect`; stock's fit, which the 168 px cache and the pane keep, stretches 320 x 240 or 240 x 320 to 320 x 320 before the page could fit it) and never falls back to stock's own resize (which would stretch it). The job searches only the source stock chose: 2 the embedded art only, 3 the folder's only, and the other is never a substitute (a 200 x 200 embedded picture beside a 600 x 600 folder cover, or an embedded format the worker cannot read, makes no file and stock's embedded picture stays; any other source word adds no job). The worker keeps a picture only when its longer side is 320 (so art under 320 px makes no file and stock's picture stays: no quality could be gained), publishes through `.tmp` and a rename, writes no cache file or marker. A busy worker or orphan (`cc_build_open` refuses) is retried every tick for `BC_TRY_MS` (6 s); a running job is given up on after `BC_RUN_MS` (10 s) (`cc_build_stop`, never waits; the worker keeps the orphan rules of [coverflow](coverflow.md)). The page never stops a set it does not hold.
- **Picture:** a finished job (`cc_build_done >= cc_build_total`) is joined (`cc_build_stop`), its file decoded by `cc_decode_fit` and fitted into the bitmap by `cc_fit`: the whole picture (never cropped) inside 320 x 320, centred over `#141414` (the page's colour), an exact area average (`ar_push`). The worker's files have a longer side of exactly 320, so the fit is a pixel copy (a square fills the bitmap, a 320 x 240 picture sits at y 40 with `#141414` bars), and a picture of another size (not made by the worker) is filtered, up or down, never nearest-sampled. A missing, corrupt or too large file, a failed decode or a bitmap that cannot be made gives up for the track (stock stays, no retry). The file is removed after the decode.
- **Server track** (`sba_rec_track` knows the playing record, streamed or downloaded): the page's key is the record's synthetic `REC_ID`, never the path (a stream address carries the login and is not a file), and no job runs for a stream (stock makes no picture for it, `bc_start_job` refuses a path that is not a file). The picture is the cover file Now Playing draws (`sba_rec_cover`, asked for when it is not cached), decoded and fitted into the same 320 x 320 bitmap by `cc_decode_fit` (the 168 px file enlarged by the exact average) and drawn by the same paint; `bc.srv` marks it, so no source word is compared. A stream whose cover is on its way keeps stock's page and asks again every tick for `BC_SRV_MS` (60 s); a stream the server has no picture for is given up (`BC_GAVE`). A downloaded track without a server picture takes the job on its local file as a local track does.
- **Paint:** the cover widget's `EVT_AFTER_PAINT` draws the bitmap 1:1 over the widget (`canvas_draw_image`) only while the picture is ready and the playing track's key is the one it was made for (checked on every paint). Stock keeps drawing and reloading its 264 px picture (its own refresh timer `0x5299a4` reloads on a track change); ours covers it, and a stale one is never drawn between a track change and the next tick.
- **End:** `EVT_DESTROY` (of this window only): `cc_build_stop` if held (no wait), timer removed, files removed, bitmap destroyed, state cleared. A page that never said it was gone is cleaned when the next one opens. Repeated open and close leave nothing held.
- **Kill switch / fallback:** `/mnt/mmc/m1plus-off` skips the whole thing at the hook (one `access` per page open); every failure (no widget, no timer, no bind, no worker, no file, no decode, no memory) leaves stock's page as it is. Not boot-reachable; no loop, thread or network of its own.

Not done: the page keeps stock's behaviour for art under 320 px (no upscale filter beyond what stock's `scale_auto` does), and a changed track only reuses the 264 px picture until the 320 px one arrives (the worker needs a moment, usually under a second for a local file; long for a large embedded picture).

## Tests

`test/pod/bigcover.py` (`make test TEST=bigcover/<section>`): `hook_tests` (words, `$gp`, trampoline, manifest, pins of the dispatcher and the timed open, kill switch, failed init, null window, missing widget, failed binds or timer); `job_tests` (the request with its source word (2, 3), polling, the 320 x 320 bitmap equal to the file's pixels, non-square and small and big sources, no art, corrupt file, no memory, busy worker, orphan, add/start failures, a hung job, cover source, stream, empty queue, dark screen); `life_tests` (track change with a stale result, destroy during extraction, repeated open/close, a page that never ended). `test/coverflow.py` covers `cc_fit` on the host. `test/pod/coverart.py` section 8b runs the real worker (`cc_build_add_aspect`) on 320 x 240, 240 x 320 and 320 x 100 originals (embedded and folder: kept in shape), a square 320 (a copy), 640 x 480, a 300 px original (no file), source 2 with a small or unsupported embedded picture beside a valid folder cover (no file, the folder is never looked at), source 3 with a different embedded picture present (the folder only) and checks the pane's `cc_build_add_file` is unchanged (stretches at exactly its size). `job_tests` also has source 5 (no job, nothing drawn), a source that turns into 5 or 1 or the other of 2 / 3 mid-job (dropped, asked again with the new source) and the parser's path buffer empty, another track's or a prefix (no request); `life_tests` track changes 3 -> 2 and 2 -> 3 with the parser still on the last track (no request until its path buffer is the new track's).

## Device checks (not done)

Sharpness of a 600 px embedded and a folder cover on the timed page; a non-square cover's bars against the page; the first seconds of a track change on the page (stock's 264 px picture, then ours); that the page still closes on tap; Wi-Fi/Albums builds running at the same time (the picture then waits, or stays stock after 6 s).

## Idle view

**Sources:** `patch/bigcover.c` (`bc_timed_open`, `idle_view`, `idle_choice`, `idle_set`), `patch/m1plus.c` (`ACT_IDLE`, `ACT_IDLESET`), `tools/pod.py` (`IDLE_SITE`, `IDLE_PINS`, `COVER_MODE`), `tools/pod_pages.py` (`IDLE_PAGE`); tests `test/pod/bigcover.py` `idle_tests`, `idle_setting_tests`.

Settings > Now Playing > **Idle Display** chooses where the timed view goes: **Off**, **Album Cover** (stock's page, sharpened above), **Cassette** or **Vinyl** (the pages of [tape](tape.md) and [vinyl](vinyl.md)). A page the timer opened closes on a tap, like stock's Album Cover page: Cassette on a tap anywhere (the screw included), Vinyl on a tap on the record (the chevron closes as always; the keys keep their actions). The same pages opened from the More sheet are unchanged (tap pauses). Hardware Back is not part of this.

- **Setting.** The last card of Settings > Now Playing (after Cassette Mode and Vinyl Mode) is the value row Idle Display (the grey value, a chevron; `ACT_IDLE` 82, glyph `timer`) with the note "Shown after 10 seconds on Now Playing." It opens the picker `m1plus_idleview` ("Idle Display": four check rows, `ACT_IDLESET` 83, arg 0 Off, 1 Album Cover, 2 Cassette, 3 Vinyl, and the same note). Two stores make the choice: stock's Cover mode byte `COVER_MODE` `0xa05aa5` (Playback Settings > Cover mode; the timed view runs only while it is on) is Off or not, and `/mnt/data/m1plus/nowplaying-idle` says where it goes (`0\n` Album Cover, `1\n` Cassette, `2\n` Vinyl; a missing or invalid file is Album Cover; a Settings Files row). `idle_choice` reads both live each time the page is in front, so stock's own Cover mode row and ours stay in step both ways.
- **Saving.** Stock's row handler (`on_playsetback_onclick`'s case `0x4a0098`, pinned in `IDLE_PINS`) flips the byte with `xori`, saves `write_int_config(value, "SYSSET", "COVERMODE")` (`0x4d6a2c`: `toolsWriteConfig` on `/mnt/data/config.ini`; 0 when done, -1 when it could not open the file) and stores the byte. `idle_cover_mode` does the same but saves first and stores the byte only on 0. A destination pick writes the file atomically first (`home_write_atomic`), then turns the byte on if it was off; if that save fails the file is put back (or removed if there was none). Off only turns the byte off and keeps the destination for when it is turned on again; a pick that changes nothing saves nothing. A failed save changes neither file, byte nor check.
- **Hook** (payload hook 24, not boot-reachable): the timer callback `0x53cf48` (stock's Now Playing 500 ms tick) reaches `0x53d0ec` only with the Cover mode byte on and `playing_page` on top and the countdown `0x97ccd0` at zero; `jalr navigator_to` becomes `jal bc_timed_open`. The delay slot (`a0 = "bigcover_page"`), the `lw gp` after the call and the countdown reset to 20 are stock's. `IDLE_PINS` pins the callback's prologue, the Cover mode test, the `playing_page` strcmp, the countdown words, the GOT loads, the call and its slot, and the Cover mode row's words.
- **Dispatcher** (`bc_timed_open(name)`): the kill switch, a name other than `bigcover_page`, a missing or invalid file or Album Cover: stock's `navigator_to(name)` (hook 23 still sharpens the page). Cassette: `tape_open_idle()`; Vinyl: `vinyl_open_idle()` (`tape_open` / `vinyl_open` plus the page's `idle` flag, which makes a tap close it and is cleared when the page is destroyed; the More sheet still calls the plain functions); on -1 stock's `navigator_to(name)` exactly once. Now Playing is not closed and `bigcover_page` is not opened underneath; the page opens over Now Playing, whose timer callback does nothing while another window is on top.
- **Already open.** `tape_open_idle` / `vinyl_open_idle` return 0 when their window exists and open nothing, and leave that page's flag as it was (a More-opened page keeps pausing on tap). The dispatcher then does nothing more: no second window, no timer, no stock cover page over the user's view, and stock's countdown restarts as after any open (so a stale window is retried every ten seconds). A page destroyed in the meantime opens fresh. (Reaching this needs Now Playing on top while the page is still in the window stack; Back normally destroys it.)
- **Fallback.** Everything off the happy path ends in stock's call; the kill switch is read at the hook (one `access`); no state, thread or timer of its own.
- **Not done:** Lyrics as a destination (Lyrics is the slide view's second pane of Now Playing; switching it needs `slide_view_set_active` on the window's `slide_view`, which is not pinned or called anywhere, the lyrics pane's own state and, because stock resets the countdown to 20 after every timed open, would pull the user back from any other pane every ten seconds) and a delay choice (stock resets the countdown at `0x97ccd0` to 20 from several sites).

Device checks (not done): the Settings row and picker on the device; Cassette and Vinyl opening about ten seconds after Now Playing with the matching choice; Back and the pages' close on tap returning to Now Playing and the next open ten seconds later; stock's Cover mode row and ours agreeing after either changes; the kill switch.

## Handover

None: the Lyrics and delay choices above are the open ideas.
