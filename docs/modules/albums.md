# Albums

**Sources:** `patch/albums.c`, `patch/viewsort.c` (the "..." card), `patch/grid.c`, `patch/covercache.c`,
`tools/pod_ui.py` (`navbar(albums=True)`, `view_sort_card`). **Tests:** `test/pod/albums.py`, `test/coverflow.py`.
Previews: the Albums panels in `tools/preview_icons.py`.

Albums opens a grid or list in the last selected mode. Tapping an album calls
`cc_open_album`; Back returns to the same position. Cover Flow opens above this page.
If the window cannot open, the Home dispatcher opens stock Albums.

Scoped to an artist or composer: a tap on a row of the Artists page (`albums_open_artist(list, row, scope)`)
opens the same window and mode on that artist's albums. The page holds a copy of the artist's row and the album list
and cache keys from `coverflow_artist_albums` (`patch/coverflow.c`: `loadAlbumList(0xf004 / 0xf005, artist)`, each album
keyed like the library album of the same name, the case-insensitive index from 24 albums; shared with Cover Flow's
scoped page). The stock trailing "All songs" row (id -2) is kept as the last tile with two albums or more (dropped with one):
same tile size, the cards' placeholder disc (key 0: no cache file, never scanned or built), "All Songs" (stock key
`local_allsong`) over the artist's name. Its tap opens our Songs page on every song of the artist (`songs_open_artist`;
the stock page on the All songs row if it will not open, and for a composer, which has no songs page, as Cover Flow's card). The large title is the name, fitted with an ellipsis (296 px; the navbar's small title, 110 px, is fitted too); an empty
list says "No albums". An album tap is `cc_open_album(row, scope, index)`: class `0xff01` / `0xff02`. The Cover Flow
button opens Cover Flow scoped to the same artist (`coverflow_artist`) above the page; Back returns here, then to
the Artists page. The mode file is shared with Home > Albums, toggling writes it, and Cover Flow is never stored.
The cache scan uses the scoped keys (`cc_build_near_step`'s `keys`; it skips the All songs row). The deque, list and keys are freed on destroy.
If the window cannot open the caller opens Cover Flow on the artist.

through it (`0x60b1c8..0x60b1e8`). The content view and `virtual_h` both hold the full
content height as 32-bit integers. Empty content is hidden and insensitive.

Switching the mode (the card's Grid or List row) stops a running scroll animation, drops tiles, changes geometry and preserves
the first visible album. It moves the tick to the new view and writes the choice with
`home_write_atomic`. Missing required style labels or content widgets close the page.

## The "..." card, search and order

- **Search Albums** (the card's first row, slot 6, below): closes the card, then `search_open_in(SEARCH_ALBUMS)` (the Search page scoped to albums, [search](search.md)); the library search (`search_open`) when that will not open. The scoped artist page has the same row.
- **The card** (`btn_more`, x 214): an Apple-style grouped menu built by `view_sort_card` and run by `patch/viewsort.c`, a helper the other pages can reuse. Full-window scrim `#00000082` (a tap closes the card), card right edge 311, top y 52, seven 48 px rows (336 px high; the artist-scoped page has six, 288 px, below), pressed 6 % white, on the card's own glass `vs_glass7` (`mod_icons.GLASS_VIEWSORT`, 72 x 336, drawn `patch3_x`; one picture per height, the same pane and radius as the Playlists menu's). The first row is **Search Albums** (slot 6, search glyph `pod_ic_vssearch` at x 38, label at x 66, no tick), a group of its own; then the **View** group, **Grid** and **List** (20 px glyphs `pod_ic_vsgrid` / `pod_ic_vslist` at x 38, labels at x 66), a tick on the current view, a tap on the other view switches (the ticked one only closes the card); then the **Sort** group, **Title**, **Artist**, **Recently Added**, **Year** (labels at x 38), a tick on the current one. The tick column is x 14 (14 px `sg_tick`, centred in the row) on every row; a card of action rows only (nothing tickable: the Playlists list-plus card, a playlist file's Folders card) has no tick column: `vs_fit` moves the glyphs to x 14 and the labels to x 42 (the same 28 px glyph-to-label gap) at every open and narrows the card to match (still `VS_CARD_MIN`..292); the glyph column starts 10 px after the tick, and a label sits 8 px after its glyph (`VS_TICK_X`, `VS_TICK_W`, `VS_GLYPH_X`, `VS_GLYPH`, `VS_LABEL_X`, `VS_LABEL_X_GLYPH` in `patch/offsets.inc`). 13 % white hairlines between the groups only: under Search Albums (the `vs_hair` widget, 1 px at y 48, hidden with the row) and between List and Title (the first sort row's top border); none between the rows of a group. The ticked sort row shows a second line, 15 px `#AAAAAA`, with the direction (below). The card is as wide as its widest label or direction line from its own x plus 16 px, 206 (`VS_CARD_MIN`) to 292 px, measured again at every open (`vs_fit`; a text that cannot be measured leaves 292). Strings: `Search Albums`, `Title`, `Grid`, `List`, `A–Z`, `Z–A`, `Newest First`, `Oldest First` (`tools/pod_i18n.py`, 13 languages); `Artist`, `Recently Added`, `Year` existed. The mock-up's geometry (48 px rows) is used as drawn; the Songs Sort card is the same card (four rows).
- **Order and direction.** A sort row saves `albums-sort` (`cc_sort_mode_set(mode, rev)`, atomic; a failed save changes nothing), rebuilds `al.order` and starts the list at the top (tiles dropped, scroll 0, the cover scan restarted from the first album in view). A row that is not ticked starts in the order's default direction; **tapping the ticked row reverses it**. Defaults: Title and Artist A-Z, Recently Added and Year newest first; reversed they read `Z–A` / `Oldest First` in the ticked row's second line (`vs_dir`, `vs_menu`). The file is one character: `0` Title, `1` Artist, `2` Recently Added, `3` Year, or `a`, `b`, `c`, `d` for the same order reversed (`cc_sort_rev`); missing or anything else is Artist, not reversed (so a file written before the direction existed reads as the default direction). The retired Settings > Library > Album Order file (`album-order`) is moved into it once (`0` Title, else Artist; only when `albums-sort` is missing) and deleted by `cc_sort_mode` ([settings](settings.md)). `cc_album_order` (`patch/covercache.c`) is shared: Title is the stock list (NULL order, `getAllAlbum` grouped by album NOCASE, title sort; reversed it is an explicit order, the stock one backwards); Artist is the album row's artist then title (the name order of [artists](artists.md): digit runs by value, "The " ignored, CJK by pinyin initial); **Recently Added** ranks each album by its newest song and **Year** by the earliest year tag (1000 to 2999) among its tracks, newest year first, albums with no year last. Both read the library song list once (`loadLocalClassList(0xf001)` under `sort_flag` 3, `time_create desc`; the flag and the browsing class are put back; each song finds its album by name in a copy of the rows ordered by name, a binary search, on the UI thread). A song with no album is ignored; ties and albums with no song keep the stock order; with no song list (an empty library, no memory) the stock order is used. Reversed, the key comparison flips: Z-A, oldest song first, earliest year first; "Unknown Album" (id -1), the scoped All Songs row (id -2), albums with no year and albums with no song stay last in either direction (ties keep the stock order). Grid, list and Cover Flow (`coverflow_open`, the Cover Flow button) all call `cc_album_order` (the saved mode and direction); the artist-scoped page and Cover Flow call `cc_album_order_mode(albums, cc_scoped_sort(), cc_sort_rev())` (below). Home's cover scan and the Cache page's lists walk the same order.
- **Artist page: pills and years** (scope `CLASS_ARTISTS`; the library page and a composer's have neither). Under the large title the **Play** and **Shuffle** pills of the Songs page (`btn_play` / `btn_shuffle` in the asset's content view, flat `#1E1E1E`, pressed `#333335` (`ROLE_PRESS_PILL`), 40 px high at y `SG_PILL_Y` 52, radius 20, glyph + 18 px label centred by `pod_centre_pill`; hidden and insensitive in the asset, shown by `al_open` only for an artist). **Play** is 145 wide at x 10 (`AL_PLAY_X`, `AL_PLAY_W`: x 10 .. 155) and **Shuffle** 145 wide at x 165 (`AL_SHUFFLE_X`, `AL_SHUFFLE_W`: x 165 .. 310), a 10 px gap, the same 145 as the Songs page's select-bar pills (the Songs page's own pills stay 129 wide, `SG_PILL_W`, because of its rail). The block ends at `AL_PILLS_END` 92: the grid's first gap (`GRID_ROW_GAP`) follows it, the list's first row is `GRID_ROW_GAP` under it (`al_top()`: 102 in list, 92 + 10 in grid; 52 without pills). The small title still shows at `SG_COLLAPSE` 46 (the pills are under the title, as on Songs). **Play** = every song of the artist in order from the first, **Shuffle** = the same list in the stock Shuffle mode from a random song, both `songs_play_artist` (`patch/songs.c`): the two stock queries of `songs_open_artist` (`songs_artist_list`: `loadAlbumList(0xf004)`, `loadAlbumdetailList(0xff01, the All songs row)`) then `so_play(0xff11, list, 0 / -1, SO_IN_ORDER / SO_SHUFFLE, sg_open_player)`: what the Songs page's pills do on an artist's list. The grey line under each album is its **year**: `al_open` reads the artist's songs once (`songs_artist_list`) and `cc_album_years` (`patch/covercache.c`, the Year order's `so_scan`: earliest year tag 1000..2999 among the album's songs, a binary search per song over the albums by name) fills `al.years` by stock row; an album with no usable year has an **empty** second line, and the All Songs tile/row has none either (no artist name under it). An album shared with other artists (a compilation) takes the earliest year among this artist's tracks of it, which can differ from the Year order's library-wide year. Tests: `test/pod/artists.py` `scoped_pills_tests`.
- **Scoped artist page.** The same page and one shared order (`albums-sort`, direction included): the artist's albums follow it (the All Songs row stays last). One artist has one artist name, so the card has no **Artist** row: `vs_bind(..., sorts)` takes the set of sort rows offered (`VS_ALL_SORTS & ~(1 << CC_SORT_ARTIST)` here), hides the others (`vs_item1`; hidden and insensitive, the widget names stay in the asset), packs the rest from the top in `vs_fit` (Search Albums, Grid, List, Title, Recently Added, Year: 6 x 48 = 288 px) and sets the card's `bg_image` to `vs_glass6` (`VS_GLASS6`, `mod_icons.GLASS_VIEWSORT6`, 72 x 288). When the saved order is Artist the page shows the albums in Title order (the stock list; reversed when the saved Artist is reversed) and ticks Title (`cc_scoped_sort`); a row of this card writes `albums-sort`, so it changes the library Albums page too. A tap on that ticked Title row reverses the shown direction and saves Title (`0` / `a`). ## Covers and painting

The shared grid supplies tile records, rounded artwork, ellipsis fitting, painting and hit
testing. Recently Played uses the same helpers. Covers come from
`r<album-key>-168.jpg`, reduced by an area average of the centered square.
An absent file or empty “no art” marker uses the placeholder disc.
A `.bad` marker (an album whose extraction hung, `docs/modules/coverflow.md`) also keeps it out of the missing set.

Twelve resident tiles cover visible cells, prefetch and recent history. Grid artwork uses
about 1.1 MB including the placeholder; list artwork about 130 KB for the ring. The copied
album list adds about 0.3 KB per album. A decode temporarily holds the 168 px source.

Paint draws resident covers and text only: no image decoding, bitmap allocation or timer
creation. Text is measured and ellipsized once per tile. Drawing is limited to the 400 px
viewport; partial text lines are omitted. The stock scroll view clips the canvas.

The 16 ms loader decodes at most one cover per tick, prioritizing visible cells nearest the
viewport center, then one grid row or two list rows ahead in the scroll direction.
Visible tiles are retained; other tiles use LRU replacement. Decoding pauses during a stock
drag or running scroll animation (`grid_moving`) and resumes when it ends.
Backgrounding stops the loader and cancels this page's cache build; foregrounding restarts missing work.
If scroll events cannot be registered, the loader polls while the page is open.

## Cache building

The shared `cc_build_*` worker builds missing cache files without blocking page open.
A 50 ms startup timer scans in batches of 64 albums, 20 ms apart, nearest the initial
viewport first. The worker starts after the scan finishes; scrolling does not reorder it.
A 500 ms poll makes placeholder tiles eligible for reload as files arrive.

Only one page owns the worker. Opening Cover Flow releases the Albums build first.
Destroy stops owned work and removes timers. `cc_build_stop` never waits for the thread: a worker
that has exited is joined and its set freed; one still inside a job (stock's art call cannot be
interrupted, and can be slow) is cancelled and orphaned, keeps the set and is joined and freed by the next
`cc_build_open` / `cc_build_busy` / `cc_build_orphan` after it exits. Meanwhile `cc_build_open` refuses and
`cc_build_busy` is true; the Albums and Songs start timers ask again every 500 ms while `cc_build_orphan` (true for 10 s after the orphaning, then they stop until the next foreground or open).
A refused timer/thread, busy worker or less than 16 MB free space leaves placeholders.
A completed scan with no missing files is not repeated during that page's lifetime.

## Input and validation

The stock scroll view owns drag, fling and end stops; [list gestures](gestures.md) handles
coasting catches. Page listeners return without consuming events. A release on the original
cell within 10 px on both axes opens the album. Drag, abort, backgrounding or a touch that
stops coasting clears the press and opens nothing. List presses use `#333334` (`LIST_PRESS`, the pressed-row role colour).

Tests cover the capsule, the card (asset: groups, two hairlines, tick column, glasses; the Search row and its fallback; ticks, each order, the saved file, the View rows, the fit; `reverse_tests`: the direction line, a tap on the ticked row, the saved letter, special rows last; Cover Flow in `test/pod/sort.py`; on the artist's page `test/pod/artists.py` `scoped_sort_tests`: the rows hidden and packed, the 288 px card and glass, Artist shown as Title, each order and direction, the shared file, the artist's Cover Flow order); `test/pod/i18n.py` measures the card's texts in all 13 languages, both modes, real stock layout and pointer handlers, large-library content
heights, tile bounds, loader deferral, cache-worker ownership, persistence and failure paths.
Real frame timing and canvas/text appearance require [device checks](device-checks.md).
See [album page](album-page.md) for album opening, [Cover Flow](coverflow.md) for the shared
cache worker and [rows](rows.md) for common library styling.

## Handover (view sort menus)

Phase 1 is this page; phase 2 is the Artists page (with Genres and Composers); phase 3 is the Songs page (Title, File Name, Format, Recently Added, [songs](songs.md)); the Folders page ([folders](folders.md)) and the Playlists page ([playlists](playlists.md)) follow, so **every page with a "..." menu is done**. How a page uses the helper:

- Reuse `patch/viewsort.c` (`vs_bind`, `vs_view`, `vs_menu`) and `tools/pod_ui.py` `view_sort_card` (its arguments give a page's own row texts and view glyphs): the page's asset appends the card last (names `vs_*`), binds it at open and keeps its own state (current sort, mode). The asset always has the four sort rows, the two view rows, the Search row and the Select row (`VS_SORTS` 4, `VS_ROWS` 8 in `patch/offsets.inc`; the card is built seven rows high, Select sharing Grid's place until the payload packs it); a page passes the `sorts` mask to `vs_bind` (`VS_WITH_VIEWS` offers the two view rows, `VS_WITH_SEARCH` the Search row, whose click arrives as `VS_SEARCH`, `VS_WITH_SELECT` the Select row (`VS_SELECT`, a check-circle glyph `pod_ic_vsselect`, the second row); sort row 0 must stay) and gets the card packed; `vs_offer(v, mask)` changes the mask later (the Songs page's Recently Added drops Select in its albums view) and packs an open card again. A row not offered is hidden and insensitive; `vs_hair`, the hairline under the first group (Search, Select), sits under the last of them and is hidden when none is offered or nothing follows; the first sort row's top border (the hairline between View and Sort) goes when no view row is offered. The view rows are the page's second group when it is not Grid / List (the Artists page's Show group: a click arrives as `VS_SORTS` or `VS_SORTS + 1`, `vs_view` ticks the second when `list` is set). The card always has the glass of its row count (`VS_GLASS_FMT`: `vs_glass7` 336 px, `vs_glass6` 288, `vs_glass5` 240, `vs_glass4` 192, `vs_glass3` 144, `vs_glass2` 96 and `vs_glass1` 48 px exist); a glass is height-specific (`mod_icons.GLASS_VIEWSORT*`), so another height needs its own picture in `mod_icons` (generated with `np_images`, the PNG committed in `assets/icons/png`). A page keeps its sort and direction (`vs_menu(on, sort, rev, list)`) and its handler reverses the ticked row. `vs_dated(v, mask)` picks which sort rows read Newest First / Oldest First instead of A–Z / Z–A (default rows 2 and 3; the Songs page passes row 3 alone).
- Each page gets its own order file (`albums-sort` here; list it in `pod_pages.SETTING_FILES` and `patch/setfiles.c`, kept in the same order) and its own order function; this page's is `cc_album_order`. The Artists page (with Genres and Composers) is done: Search, a Show group and Name in `patch/artists.c` ([artists](artists.md)). The Songs page is done ([songs](songs.md): its navbar buttons Search, Sort, Select and Recently Added's view toggle are folded into the one "..." card, a mask per list from `sg_offers`: the library `vs_glass5`, the other lists `vs_glass1`, Recently Added `vs_glass3` / `vs_glass2`; Search is back as a navbar button on the Songs page, x 168 like Cover Flow on Albums; its Z-A reverses the stock list in place and the play queue with it). The Folders page is done ([folders](folders.md): "..." with Select and Name, Date Modified, Type in `vs_glass4`, `folders-sort`, `vs_dated` row 1, the sorted `vis` index and the reordered play queue `so_play_with`). The Playlists page is done ([playlists](playlists.md)): list-plus | "..." | Now Playing (Songs' pattern); two cards on one `vs_card` (the list-plus button's in `vs_glass4`, the "..." in `vs_glass3`): the list-plus button's four action rows (`VS_SEARCH`, `VS_SELECT`, `VS_ACT2`, `VS_ACT3` = slots 6..9: New Playlist, Import, Export, Delete Playlists; the extra two slots exist only in its asset and `vs_bind` finds them only when the mask asks) and the "..."'s Grid / List and Name (sort slot 0; `playlists-sort` `a` = Z–A; the displayed order through `pl.ord` over the untouched stock copy); Recently Added was tried and dropped (ids are reused, no creation time), Recently Modified and Number of Tracks were not offered (no per-playlist time; a count needs every playlist read first).
- The widget names are per window, so the same `vs_*` names work on every page. Tests: `test/pod/albums.py` `card_asset_tests`, `sort_card_tests` (the card, the fit with `ListMachine`) are the model; `VS_WIDGETS` in `test/pod/harness.py` lists the widgets a machine needs for an Albums page (eight rows). Machines share widget names, so a page opened in a test over another (Artists' All Songs row opening Songs) re-binds a shared `btn_more`.
- Open points: Recently Added and Year are not device-tested (a rescan rewrites `time_create`, [recent-albums](recent-albums.md)).
